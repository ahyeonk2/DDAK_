# DDAK

같이 해야 할 일을 가볍게 확인하는 대학생 팀플 투두 앱입니다. 화면은 cream canvas `#fbfaf9`, 820px 중심 콘텐츠, 사람별 작은 할 일 목록과 최소한의 색상 점으로 구성했습니다.

## 다시 시작하기

Mac에서는 이 폴더의 **start.command**를 더블클릭하세요. 터미널이 열리면 브라우저에서 **http://localhost:5173/** 으로 접속합니다. 실행 중인 터미널을 유지하고, 종료는 `Ctrl+C`입니다. 이미 실행 중이면 주소만 다시 열면 됩니다.

Node.js 24 이상이 필요합니다. 이 컴퓨터에서는 설치된 Codex Node 런타임도 자동으로 찾습니다. 다른 컴퓨터에서는 Node.js 24와 npm 또는 pnpm을 설치하세요.

터미널 실행:

```sh
pnpm install
pnpm build
pnpm start
```

개발 중 자동 반영:

```sh
pnpm dev
```

Vite는 5173, 개발 API 서버는 3001 포트를 사용합니다. `pnpm start`는 빌드한 웹 화면과 API를 한 서버의 5173 포트에서 제공합니다. `pnpm preview`는 API를 포함하지 않으므로 로그인 앱 실행에는 사용하지 마세요.

## 사용 흐름

1. Google 로그인. 최초 가입 시 검증된 Google 프로필 이름을 닉네임으로 저장합니다.
2. 내 팀프로젝트. 신규 계정에는 프로젝트를 자동 생성하지 않습니다.
3. 팀프로젝트 만들기. 이름, 수업(선택), 마감, 목표, 하기로 한 일과 하지 않을 일을 정합니다.
4. 방 생성 후 초대 링크를 복사합니다. 받은 사람은 Google 로그인 뒤 참여할 수 있습니다.
5. 방에 들어가면 약속한 목표와 팀원별 투두가 보입니다. 본인의 할 일만 추가·수정·완료할 수 있습니다.
6. 친구의 미완료 할 일에는 작은 눈 버튼으로 흔적을 남길 수 있습니다.
7. 새 범위를 더하면 기존 범위 하나를 덜어냅니다. 마무리는 방을 만든 사람이 할 수 있습니다.

현재 Google 클라이언트 ID는 아직 제공되지 않았습니다. 로그인 구현은 연결 대기 상태이며, 실제 Google 로그인 완료를 검증하지 않았습니다. 설정 전에는 ‘로그인 없이 화면 미리보기’로 화면 흐름을 볼 수 있습니다. 이것은 Google 로그인이나 실제 계정이 아니며 공유 API 접근 권한도 주지 않습니다. 운영 환경에서는 이 미리보기 진입점이 표시되지 않습니다.

## Google 로그인 연결

[GOOGLE-SETUP.md](./GOOGLE-SETUP.md)를 따라 웹 애플리케이션 OAuth 클라이언트 ID를 `.env`에 넣고 서버를 다시 시작하세요. 클라이언트 비밀 키는 사용하지 않습니다.

## 데이터와 권한

- 실제 로그인 사용자와 프로젝트는 서버 SQLite `data/deoreonae.sqlite`에 저장됩니다.
- 세션은 HttpOnly/SameSite 쿠키를 사용하고 서버에는 세션 토큰 해시만 저장합니다.
- Google ID 토큰은 Google Auth Library로 서명, audience, issuer, 유효기간을 검증하고 nonce도 확인합니다.
- 회원 목록, 참여 권한, 본인 투두 수정 권한은 서버에서 확인합니다.
- 방 데이터는 5초 간격 및 창 복귀 시 갱신됩니다.
- 화면 미리보기 데이터는 `deoreonae-preview-v2` localStorage에 별도로 저장합니다.
- 기존 버전의 localStorage 데이터는 삭제하지 않았습니다. 기존의 익명 데모 데이터를 실제 Google 계정에 자동 귀속시키지 않습니다.
- DB, `.env`, 세션 데이터는 소스 압축 파일에 포함하지 않습니다. DB를 삭제하면 실제 계정·프로젝트 데이터도 사라집니다.

## 검증

```sh
pnpm test
pnpm build
```

서버 테스트는 Google 검증 경계만 테스트용 검증기로 대체해 계정 생성, 닉네임 적용, 빈 첫 목록, 방 생성, 초대 참여, 본인 투두 권한, 동시 저장, 범위 교환, 세션 종료, 서버 재시작 후 보존을 검사합니다. 테스트 로그인용 HTTP 엔드포인트나 실제 서버의 인증 우회는 없습니다.

## 운영 배포

이 버전은 Node.js 서버와 지속적인 SQLite 저장 디스크가 필요합니다. `dist`만 정적 배포하면 로그인과 공유 기능은 작동하지 않습니다. 인터넷 서비스로 제공하려면 HTTPS 주소에 서버를 배포하고 해당 주소를 Google OAuth 설정과 `APP_ORIGIN`에 등록해야 합니다. 서버 인스턴스 하나를 기준으로 구현되어 있습니다. 온라인 배포는 아직 진행하지 않았습니다.
